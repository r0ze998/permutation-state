## 1. 結論

- 新しいゲーム名は **「Wylls」** です。Eternum のような一枚の大きな世界で、シーズン途中からでも参加できます。
- 地図は、人が増えると外側へ自動で広がります。1シーズンで入れる人数の上限は、シーズン開始時に公表します（初期設定で約10万〜13万人分の土地）。
- **第1シーズンは Solana 本体だけで動かします（決定 O8）。** 今の48人のゲームを「短期戦」として残す案はやめました。MagicBlock の高速レーン（ER）は使いません。専用の高速レーンに移す案（X1）は、将来の拡張として残します。
- **乱数は drand の quicknet だけを使います（決定 O1・O2）。** MagicBlock の乱数（VRF）は、もう使いません。
- **準備段階（M0）はまだ終わっていません。** 2回目の作業で、実験のやり直し（計算量の測り直し、手数料妨害の実験）、お金の仕組みの調整、勢力の個性の調整を行いました。合格条件のうち「手数料妨害（C4）」は、書いたとおりの条件では達成していないので、条件の書き方を直しました（9章）。

4つの設計案を3人の審査役（面白さ・安全性と規模・作りやすさ）が採点し、次の組み合わせにしました（改訂2から変わっていません）。

| 部分 | どの案から取るか | 理由 |
|---|---|---|
| ゲームの中身 | E4 案 | 面白さの審査で最高点（8.5点） |
| 土台の仕組み | E3 案 | 安全性の審査で最高点（8.0点）。「タダで世界を止められる穴」がない唯一の案 |
| 勢力の点数の付け方 | E3 案（改訂2で採用） | 大きい勢力に入っても得をしない |
| 妨害への守り方・運営の預かり金 | E1 案 | 運営が不正をすると運営自身が損をする |

E2 案（小さな州を並べる案）は採用しません。1つの州が止まると地図全体が止まってしまう構造があり、また「一つの大きな開かれた世界」になっていないためです。

## 2. どんなゲームになるか

**一言でいうと：** あなたは一つの文明に属する6つの勢力のどれかの市民です。自分の村を持ち、軍を育て、行き先を秘密にして軍を送り出します。10分ごとに鳴る「鐘」で、同じ場所に着いた軍どうしが一斉にぶつかります。

- **一つの文明、六つの勢力。** 地図の中心には、文明全体で建てる「エンジン」があります。進むと全員の技術の上限が上がり、賞金の一部もエンジンに貢献した人に配られます。
- **勢力ごとに個性があります（ドクトリン）。** 最初の村は自分の勢力の土地（扇形の本拠地）に建てます。そのため、勢力ごとのまとまりと前線ができます。
  - **改訂3で決めたルール（決定 O5）：「生産量や研究量など、点数に直接かかる数字を増やす個性は付けない」。**
  - 理由：最初の案では、研究が20%増える勢力（Lumen）が、600シーズン中99.5%で勝ちました【シミュレーション】。勢力の成績はシーズンごとの差がとても小さい（約1.4%）ので、小さな上乗せでも毎回勝ってしまいます。
  - **改訂3.1の結果：** 調整した表で、1,500シーズン分のシミュレーションを行い、**6勢力すべてが目標の勝率（16.7% ± 2ポイント）に入りました**（15.6%〜17.4%）【シミュレーション】。調整に使っていない別の乱数で確かめています。
  - 残す個性は、兵種・構えの得意・移動の速さ・城壁・維持費などです。改訂3.1では、F（鉄）の重騎兵をB（潮）の軽騎兵と別物にしました（同じ兵種で、どの構えでも攻撃が1割強い）。「2つの勢力が同じ軍を持つ」表は、プログラムが受け付けません。
  - **まだ仮の表です。** 市場・荷車・転移石・戦争の合図など、シミュレーターにまだない仕組みにかかわる個性は、理屈で小さめにしてあるだけです。その仕組みができたら（M1〜M3）、そのたびに測り直します。
  - 自動テスト：コードを変えるたびに180シーズン分の簡易チェックを行います。わざと偏らせた3つの表（最初の案、Fを旧重騎兵にした表、Aを強くした表）が必ず不合格になることも確かめます。目標の勝率そのものは、毎晩1,500シーズン分で確かめます。
- **勢力は自分たちで治めます。** 近所の代表（守護者）を選挙で選び、守護者たちの「議会」が大臣4人を選びます。大臣は和平や同盟を決め、「指令（マンデート）」を出します。指令をこなすと、決まった上限の範囲で「月桂（ローレル）」がもらえます（5章）。
- **隠れAI（シェイド）。** 運営のAIが人間にまぎれて遊んでいます。行動のルール（プログラム）はシーズン前に封印し、終了後に公開します。誰でも「ルールどおりに動いたか」を再計算して確かめられます。
- **誰でも検算できます。** すべての出来事はチェーン（公開の台帳）に記録されます。

## 3. プレイヤーは何をするか

### 参加するとき（約2分）
1. ウォレットをつなぎ、6勢力から1つ選びます。画面には各勢力の人数、ドクトリン、そして「今シーズンが終わったら1人いくらもらえるか」の見込みが出ます。
2. **参加費を USDC（ドルに連動したデジタル通貨）で払います（改訂2で変更）。**
   - **市民料**（必須）：初日4ドル。残り日数に応じて安くなり、21日目は1ドルです。
   - **月桂の賭け金**（任意）：初日6ドル。同じく残り日数に応じて安くなります。これを払った人だけが「月桂の賞金」を争います。
   - **改訂3で明確にしたこと：** 賭け金をあとから払った場合、数えられるのは「払ったあとに集めた月桂」だけです。前に集めた分をさかのぼって数えることはしません。
   - 払ったお金は、最初の村が決まるまで預かりです。24時間たっても村の場所が決まらなければ、全額を引き出せます。
3. 住みたい場所を最大3つ選びます。同じ10分間に出された希望は、公平なくじでまとめて決まります。速い人やボットが良い場所を独占することはできません。友達と隣どうしで申し込むこともできます。決まった場所は、次の鐘が終わった時点で確定します。
4. 新しい村は48時間、攻撃されない「盾」で守られます。そのあと7日間は、近くの勢力からしか包囲されません。
5. **「見張りの時間」を8時間選びます**（初期値は夜中0時〜朝8時）。この時間は、あなたの村への包囲が進みません。変更は、申し込みから24時間以上たった次の真夜中（世界標準時）から有効になります（改訂3。いつでも変えられると、約16時間の見張りを1回だけ作れてしまうためです）。

### 最初の10分（改訂3で変更）
- 農場と木こり小屋を建てます。
- 斥候を出して周りを探索します。何が見つかるかは次の鐘のあとでわかります。
- **練習試合は、ブラウザの中だけで動く「練習モード」になりました。** 本物と同じ戦闘ルールで、ルールどおりに動く相手と戦えます。チェーンには何も書かず、お金もかかりません（前の版の「アリーナ」の代わりです）。
- 最初の数回の鐘は、画面が手順を案内します。近くの蛮族の野営地に、最初の「秘密の進軍」を出します。画面には「1,034番目の鐘に到着、行き先は秘密」と出ます。

### 毎日のプレイ（15〜30分）
- 資源の回収、建築、兵の訓練をします（資源は取りに行ったときにまとめて計算されます。Eternum と同じです）。
- 指令に沿って軍を進めます。
- 中央の市場で取引し、仲間に荷車で物資を送ります。
- 守護者に投票し、請願を支持し、怪しい相手を告発します。
- 寝る前は、自分の軍の指揮を仲間の隊長に任せられます。

### このゲームの一番の面白さ
- 敵の軍が出発したことは全員に見えます。どこへ向かったかは秘密です。到着する鐘の番号だけは公開されます。
- 「あの軍はうちに来るのか、それとも隣か、ただの陽動か」を読み合います。
- **鐘が鳴った瞬間に、守る側の顔ぶれを固定します。** 行き先が明らかになってから逃げたり援軍を足したりしても、その鐘の戦いには間に合いません。改訂3では、鐘の途中で城壁が完成したり、和平が決まったりした場合も、効くのは次の鐘からだと明確にしました。
- **軍は、出発した鐘の2つ後の鐘より早くは着きません（改訂3で明記）。** 出発地で戦った結果（兵の数や疲れ）を持って到着します。同じ兵で2回続けて戦うことはできません。
- **行き先の秘密は、必ず「時限式の封」で預けます（改訂3で必須に）。** 時間が来ると誰でも開けられます。開けてくれた人（キーパー）には少額のチップが払われます。ブラウザを閉じていても、軍は自動で到着します。
- **ずるい封は、チェーン上で見破れます（改訂3で追加、改訂3.1で穴をふさぎました）。** わざと中身をでたらめにした封は、誰でもチェーン上で「でたらめだ」と証明できます【実測：証明の計算は約4.8万 CU で動きました】。証明されると、その軍はあとの精算のときになくなり、証明した人に報酬が払われます。
  - **改訂3.1で直したこと：** 改訂3の書き方では、証明に必要な「約束の値」が公開されず、でたらめな封ほど証明できませんでした。今は、出発のときに約束の値と封の両方をチェーンに記録し、チェーン自身が照合します。
  - **残ること：** 証明されるまでの間、その軍は戦い続けます（過去の戦いはやり直しません）。また、チップを0にした持ち主は「誰も開けてくれないこと」に賭けられます（そのときは軍の半分を失います）。
- 正しい封を誰も開けなかった場合は、前の版どおり軍の半分を失います。チップを払っていれば、キーパーが開けてくれるので、ふつうは起きません。

## 4. 地図はどう広がるか

- 地図は六角形のマスでできています。61マスの「州」が中心から輪のように並びます。
- 中心は中立の「コンコード」（市場とエンジン）です。そのすぐ外に6勢力の首都があります。
- 6勢力はそれぞれ扇形の「本拠地」を持ちます。どの扇形も同じ地形を60度ずつ回したものなので、どの勢力も同じ条件です。最初の村は自分の本拠地に建て、2つ目・3つ目の村はどこにでも建てられます。
- **改訂3で直したこと（地形）：** 地形を作るとき、各州の出入口と村の場所から州の中心まで、必ず通れる道を作ります。直す前は、約10%の州で「出入口どうしがつながっていない」ことがありました【実測】。
- **改訂3で直したこと（移動）：** 1回の進軍は最大4つの州までです。そのため、まっすぐ進める距離は約20〜28マスです（前の版の「32マス」は訂正しました）。
- **広がり方：** どれかの勢力の本拠地で、住める場所の55%（序盤3日間）または65%（その後）が埋まると、外側に新しい輪が開きます。開けるのは運営ではなく、ルールです。新しい輪の地形は、開いたあとに公開の乱数で決まります。誰も事前に知ることはできません。
- **最初の地図の乱数も drand だけで決めます（決定 O2）。** シーズンを作ってから10分以上あとの乱数を、ルールで先に決めておきます。そのころには参加の条件や隠れAIの名簿の封印も済んでいるので、運営は地形を先に知って有利に使うことができません。
- **人数の上限：** シーズン開始時に「最大何輪まで広げるか」を決めて公表します。初期設定は64輪で、約15万か所の土地があります。1人平均1.15か所なら約13万人分です。2つ目・3つ目の村を建てられる条件を含めても、約10万人分あります【見積もり】。
  - 土地が足りなくなったら、新しい参加は受け付けません。そのときはお金も受け取りません。
  - 払ったのに土地がない、ということは起きません。
  - 「空いている土地がいくつあるか」を参加のたびに全部数えると、混雑の原因になります。そこで、まとめて数える処理を別に用意しました（改訂3）。
  - 10日以上放置された最初の村は、土地を空けます（本人は市民のまま戻れます）。
  - プログラムの上限は128輪です。

| 参加者 | 地図の輪の数 | 州の数 | 端から中心まで（徒歩／道路・騎兵） |
|---|---|---|---|
| 1,000人 | 7 | 162 | 約2時間／1時間 |
| 1万人 | 22 | 1,512 | 約6時間／3時間 |
| 5万人 | 50 | 7,644 | 約13時間／6.5時間 |
| 10万人 | 70 | 14,904 | 約18時間／9時間 |

（この表は【見積もり】です。10万人規模では、端から中心まで徒歩で18時間かかります。）

- 遠い場所のために、道路と「転移石（ウェイストーン）」を用意します。都市どうしを短時間で移動できます。
- 5日間放置された村は「休眠」になり、攻略対象になります。
- シーズンごとに地図は作り直します。歴史は「年代記」として残ります。

## 5. お金の仕組み

### 基本（改訂2で決めた形。改訂3でも変わっていません）
- お金は2つの「財布」に分かれます。
  - **市民の財布**：市民料の80%が入ります。払った額と参加日数に応じて、ほぼ均等に返ります。探索や寄付などの「作業」の分も少し（10%）あります。
  - **月桂の財布**：賭け金の80%が入ります。賭け金を払った人どうしで「月桂」を争い、その量に応じて分けます。
- **月桂は、決まった量しか生まれません。** 村1つにつき一定量が出て、同じ州の村どうしで強さに応じて分け合います。村を奪えば、相手の月桂の一部が移ります。戦っただけでは月桂は増えません。そのため、自分の別アカウント同士で戦わせても得になりません。
- 残りの20%は運営の取り分です。これはシーズンが無事に終わるまで預かりにします。運営が隠れAIの正体を期限内に公開しない場合や、AIが封印したルールどおりに動かなかった場合は、没収されてプレイヤーの賞金に回ります。
- シーズンが止まってしまった場合は、誰でも「中止」を実行できます。**全員に払った額の100%が返金されます。**
- ゲームの中でお金（USDC）は使いません。お金で強くなる道はありません。
- 1つのウォレットが受け取れるのは、払った額の5倍までです。

### 改訂3で直したこと
- **「作業」の分け方：** 前の版は「作業量の平方根」で分けていました。これだと、同じ遊びを複数のアカウントに分けたほうが得でした。今は作業量をそのまま数え、払った市民料1ドルあたりの上限を付けます。
- **村の占領と包囲の賭け：** 賭け金を払っていないアカウントや、自分の別アカウントとの間では、月桂が移りません。別アカウントどうしで取り合っても何も得られません。
- **2回目の奪取（決定 O9）：** 同じ相手から2回目に村を奪ったときは、1回目に移った量の25%だけが移ります。3回目からはゼロです。
- **指令のごほうび（決定 O10）：** 指令をこなしたごほうび（月桂）は、賭け金を払った人にだけ出します。払っていない人には、代わりに「作業」の点が付きます。
- **役職の報酬（決定 O3、改訂3.1で方式を確定）：** シミュレーションでは、ボットが有給の役職に就けると、ボットが払った額の約1.5倍を受け取りました【シミュレーション】。そこで、**役職の報酬を足しても、受け取りは「その人が払った額の95%まで」**にしました。役職でお金をもうけることはできません。すでに払った額の95%以上を受け取る人には、役職の報酬は出ません。つまり役職の報酬は「もうけ」ではなく「時間を使ったことへの補てん」です。
  - 改訂3の「払った額を取り戻すところまで（100%）」と「役職者に月桂を出す」案は、シミュレーションで比べた結果やめました。月桂を出す案では、ボットが払った額の約1.11倍を受け取ってしまいました。100%の案は、損をしている役職者をちょうど元が取れるところまで補うので、役職が「損の保険」になってしまいます。

  - 指令は決まった種類からだけ選びます。どの種類も、24時間以上の期間のうち、好きなときに1回の行動でこなせるものにします。
  - さらに、こなした人が少ない期は、1人あたりの受け取りに上限をかけ、余りは消します（プログラムで実装済み）。

### お金で試合の結果を買えるか（改訂3.1で計算をやり直し）
Solana 本体では、手数料を払い続ければ、特定のデータを一時的に「使用中」にして、他の人の操作を遅らせることができます。

**わかったこと（実験と計算）：**

**合格条件（C4）：** 「1回の鐘の間、狙った側の提出を全部止める費用が、その鐘で決まる狙った側の戦い全部の価値の10倍以上であること」（決定 O7）。

**いまの結果【見積もり】：**
- **初期のチップだけでは、達成していません。** 1回の鐘（10分）を止める費用は、支払い口座が予測できない場合で約5,100〜14,000ドル、わかっている場合で約2,100〜5,900ドルです。本番の処理速度がわからないので、幅があります。

- **防衛用の積立を使い、キーパーが150個以上の支払い口座を使えば、どの見方でも達成します【見積もり】**（止める費用は約2.7万〜6.7万ドル）。

**守り方（決定 O7）：**
1. **防衛用の積立（ディフェンス・プール）。** 攻撃されて提出が通らないとき、キーパーは手数料を1スロットごとに2倍に上げ、上限（優先度2.0、1回の提出あたり約0.006ドル）まで対抗します。積立から出すのはチップを超えた分だけで、あとから、遅れて通ったことがチェーン上でわかる提出にだけ、上限つきで払い戻します。積立そのものは、急ぎの取引には一切かかわりません。運営が1シーズン20 SOL（約3,000ドル）を預け、使わなかった分は返ってきます。
2. **提出の受付時間を長くできるようにします。** 初期値は10分で、シーズンごとに最大30分まで設定できます。すでに始まった鐘の時間は変えません。
3. 軍の持ち主は、鐘の最中から自分で提出できます（前から可能）。
4. **チップの初期値は「優先度」で決めます。** 提出の計算量が増えても、同じ強さで競れるようにするためです。

**もう一つの穴もふさぎました。**

## 6. 何人遊べるか、なぜか

**答え：1シーズンの人数の上限は、地図の大きさで決まります。シーズン開始時に公表します（初期設定で約10万〜13万人分の土地）。ただし、Solana の処理能力の面で無理なく遊べるのは、改訂3.1の測り直しで「数千人〜約5万人」、1時間あたりの操作回数の上限を下げれば「約7万5千人」までです【見積もり】（改訂3では約10万人と書きましたが、戦闘1回の計算量が見積もりより大きかったため下げました）。**

### 今は48人が限界な理由
今のゲームは、30秒ごとに「世界全体」を1回の処理でまとめて計算します。ブロックチェーンでは1回の処理でできる計算量に上限があるため、すぐに上限に当たります。

### 新しい設計で人数が増やせる理由
- 世界全体を一度に計算することをやめます。
- 1回の操作が触るのは、「自分の村」と「関係する州1つ」くらいだけです。人数が増えても、1回の処理の重さは変わりません。
- **【実測】済みの処理：** 資源の回収、出発、到着の公開（記録を作る部分）、州の戦闘、戦闘の材料集め、参加、土地の決定、希望の提出、乱数の検証、封の検証、州の生成、市場の清算、投票、勢力の集計。
- **改訂3.1で測り直しました：** 本番で使う新しい形式（SBPF v2）で、本物のルールのプログラムを使って測りました。**戦闘1回（いちばん重い場合）は約37万〜63万 CU**【実測】で、改訂3の「約27万 CU」（仮のプログラムで測った値）の約2.3倍でした。計画では、戦闘1回あたり65万 CU を見込みます。
- **まだ【見積もり】の処理：** 到着の公開の全体、兵の集合、村の奪取、受け取り、輪の拡大など。M1 で全部測ります。

### Solana 全体への負荷【見積もり】（改訂3.1で、v2 の実測値を使って計算し直し）

| 参加者 | 普段の負荷 | わざと全員が上限まで操作し、全部の州が毎回いちばん重い戦闘をした場合 |
|---|---|---|
| 1万人 | Solana 全体の処理能力の約0.2% | 約1.8%（操作上限を下げると約1.4%） |
| 5万人 | 約1.0% | 約8.8%（約7.0%） |

改訂3（5万人で約6.9%）より増えたのは、戦闘1回の計算量が約2.4倍になったためです【実測】。10%を超えるのは、約6万人（操作上限を下げると約7万5千人）からです【見積もり】。M1 では、戦闘の計算のうち重い部分（戦場を押さえる処理と、ぶつかり合いの計算）を軽くします。

### 世界を Solana 本体に置く理由
- **ER とは？** MagicBlock の「高速レーン」です。取引が無料で速いのが特長です。
- **問題点：** 取引が無料なので、誰でもタダで大事なデータを「使用中」にし続けられます。すると世界を止められてしまいます。監査で指摘された一番大きな問題です。
- **ER で直すには？** 入口に「門番」が必要ですが、MagicBlock はその機能を公式には提供していません。門番を運営が握ると、運営が特定の人の操作だけを通さないこともできてしまいます。
- **Solana 本体なら？** 同じ妨害にお金がかかります。さらに、守る側が手数料を上げて対抗できる形にしました（5章の最後）。
- **第1シーズンでは MagicBlock を使いません（決定 O8）。** 門番つきの専用 ER が用意できたら、将来、同じプログラムのまま世界を ER に移せます。

### 乱数を drand だけにする理由（決定 O1・O2）
- **drand** は、複数の大学や企業（League of Entropy）が3秒ごとに公開している乱数です。誰も事前に知ることができず、誰でもチェーンに持ち込んで、本物かどうかをチェーン上で確かめられます。
- どの時刻の乱数を使うかは、ルールで先に決めておきます。妨害されても「待つ」だけで、結果は変わりません。
- 行き先を隠す「時限式の封」も同じ drand（quicknet）を使います。1つのシーズンでは1種類だけを使います。2種類を混ぜる案は、安全の理屈が成り立たないのでやめました。
- **MagicBlock の乱数（VRF）をやめた理由：** 受け取り口の場所が誰にでもわかり、VRF の運営側は手数料を上げて対抗してくれません。そのため、安い費用で世界中の戦いを止められました【見積もり】。2026年9月には、一部の依頼がまったく処理されない不具合も報告されています。前の版では最初の地図の乱数にだけ混ぜていましたが、その部分を調べる実験は v9 の中止で行えなくなりました。混ぜることで防げたのは「drand の運営者たちが結託する」という場合だけで、それは他のすべての乱数でもすでに前提にしていることです。そこで、やめることにしました。
- **改訂3で直したこと：**
  - 乱数の基準になる記録が、ずるい方法で2つ作れる穴がありました。2つあると、好きなほうの乱数を選べます。今は1つの鐘・1つの地域につき必ず1つだけにし、読むたびに本物か確かめます。
  - 乱数が公開される時刻を、提出の締切から**60秒以上あと**にしました。前の版では、締切の数秒前に乱数が見えてしまうことがありました【実測】。
  - 戦闘を計算するときに、その場で乱数を検証する近道はなくしました。1回の取引に入りきらないためです【実測】。代わりに、検証済みの乱数を保存した記録を、誰でも最大256個作れるようにしました。全部を止めるのは現実的ではありません。

## 10. 主なリスクとトレードオフ

- **法律のリスク（大事）。** USDC で参加費を集めて賞金を配る仕組みは、国や地域によって「賭博」や「懸賞」として規制される可能性があります。特に賭け金は、勝負の性格がはっきりしています。**本番でお金を扱う前に、必ず法律の専門家の確認を受けます**（M4 の完了条件）。地域と年齢の制限も付けます。
- **手数料を使った妨害（大事、改訂3.1）。** 初期のチップだけでは合格条件を満たしていません【見積もり】。キーパーの支払い口座も止められることが実験でわかりました。防衛用の積立と、150個以上の支払い口座で対抗します。本番に近い環境での試験（M4）が最終判断です。
- **ボット（改訂3.1）。** シミュレーションでは損をするようになりましたが、余裕は約2ポイントです。ボットが役職に就いて指令を操作すると、得をする可能性があります（指令を決まった種類だけにして防ぎます。M3 で確かめます）。
- **後から入る人の受け取りが下がった（改訂3.1）。** 後から賭け金を払う人は、改訂3の仕組みより10〜18ポイント少なく受け取ります。値段の上がり方をゆるくする選択肢があります（D22）。
- **平均的なプレイヤーは損をします。** 正直に参加画面に書きます。これを嫌がる人もいるはずです。対策として、市民料を小さくし、賭け金は任意にし、練習モードは無料にします。
- **新人向けの入口が弱くなった（改訂3）。** 短期戦がなくなったので、ゲームの中の案内と練習モードで補います。M1 と M3 のテストで確かめます。
- **自作の暗号の部分（改訂3）。** 封の形式の一部は私たちが決めたものです。正式な仕様を書き、外部の専門家に確認してもらいます。
- **口座の作り方の不具合（改訂3）。** M0 で「先にお金を送ると作れなくなる」「同じ記録が2つ作れる」という種類の問題が見つかりました。すべての作成手順にテストを付けます。
- **勢力の強さの釣り合い。** 小さな差でも勝率が大きく動きます。今の表はシミュレーションで6つとも範囲に入りましたが、シミュレーターにない仕組みの部分は理屈だけで調整した「仮の表」です。自動テストで毎回、毎晩確かめます。
- **drand への依存。** 乱数の源が drand だけになりました。drand が止まっても、ゲームは「待つ」だけで結果は変わりません。7日以上止まったら、中止して全額返金できます。
- **安全と引き換えに、手数料と少しの遅さ。** 反応は約1秒ですが、10分ごとの鐘なので遊びには影響しません。
- **作る量が多い。** 計算式、お金、検算の部品は今のコードを参考にできます。それでも、新しく書く部分が全体の半分以上あります。
- **複雑さ。** 新しい人には「村・軍・鐘・地域・指令」の5つだけを見せ、残りは少しずつ見せます。
- **隠れAIの見破り。** チェーンの記録を分析すると、手がかりが見つかる可能性があります。お金の流れを全員同じにし、AIにも投票させるなど、大きな手がかりは消しました。ただし「隣の人はAIかも」というドラマは、前の版で書いたほど強くはないかもしれません。
- **寝ている間の心配は小さくしました。** 村の包囲には、見張りの時間を除いて最低6時間かかります。攻撃の合図も出ます。夜中に知らないうちに村を奪われることはありません。
- **運営の資金負担。** 地図の保管料として1万人規模の準備で約105 SOL、防衛用の積立として20 SOL を開始時に預けます。どちらも使わなかった分はシーズン後に戻ります。

## 13. 改訂メモ

### 改訂3.1で何を直したか

改訂3の点検で、22件の指摘がありました（設計10件、実験7件、プログラム5件）。1件ずつ確かめ、22件とも本当にある問題でした。

| 何が見つかったか | 直したこと |
|---|---|
| 乱数の記録の置き場所を隠したため、締切後の提出がすり抜けられた（重大） | 置き場所を決まった場所に戻した。片づけた鐘には印を残す |
| ずるい封を証明するための「約束の値」が公開されていなかった（重大） | 出発のときに約束の値と封の両方を記録し、チェーンが照合する |
| 出発地の州が遅れると、到着の提出ができず、結果が変わった（重大） | 到着の提出は出発地を読まない。出発地の結果は、期限のない「材料集め」で読む |
| 計算量の数字が、仮のプログラムで測った古い値だった | 本物のプログラムで測った値に置き換え（戦闘は約2.3倍）。人数の目安を下げた |
| 「3つ以上のデータを止めるにはブロック丸ごと」は誤り | 名前がわかれば20〜60個を1つ分の費用で止められる、と書き直した |
| 手数料妨害の合格条件の結果を、良く書きすぎていた | 「初期のチップでは未達」と明記。条件の書き方を直した |
| 防衛用の積立の払い方が決まっておらず、悪用できた | あとから、遅れた証拠のある分だけ、上限つきで払い戻す |
| 役職の報酬の決め方が、シミュレーションの結果と合っていなかった | 「払った額の95%まで」に。役職者への月桂はやめた |
| 勢力の釣り合いの自動テストが、ほとんど毎回不合格になる設定だった | 自動テストは簡易版＋わざと偏らせた表の確認、目標の勝率は毎晩1,500シーズンで確認 |
| この日本語まとめが、確実さを言いすぎていた | 書き直した（この版） |
| キーパーの支払い口座を止める攻撃を考えていなかった | 実験で確かめた。150個以上の支払い口座を使う |
| 妨害の計算が、まだ作っていない提出の計算量に頼っていた | 計算量を幅で入れ、チップを「優先度」で決める |
| 本番の処理速度や他の取引の影響を考えていなかった | 3通りの幅で計算。本番の取引の手数料を読み取って反映した |
| 「戦いの価値」の見積もりに根拠がなかった | シミュレーションで実際に測った値も載せた |
| 2つの実験で、乱数の記録の置き場所の結論が食い違っていた | 決まった場所に統一した |
| 乱数の記録を片づけると、提出の受付が再び開いた | 片づけ済みの印を残す（テストで確認） |
| 妨害の実験の結論を、良く書きすぎていた | 「初期のチップでは未達」を見出しにした |

### 改訂3で何を直したか

準備段階（M0）で実際に作って測った結果と、その点検で見つかった指摘（24件、すべて本当にある問題と確認）と、9月27日の決定を、すべて設計に入れました。設計書の19章に、1つ1つの決定と指摘について、設計書のどこを直したかを表にしています。

| 何が見つかったか | 直したこと |

### 改訂2で何を直したか（前の版のメモ）

23件の指摘を、設計書と計算モデルで1件ずつ確かめました。指摘者の計算（`lab/redteam/rt.py`）は、そのまま再現できました。詳しくは設計書の18章にあります。（この表のうち、乱数・短期戦・妨害の費用に関する行は、改訂3で上のとおり変わっています。）
