# M1「最初の鐘」完了確認の報告（オーナー向けまとめ）

2026-10-01（同じ日に、点検で見つかった書き過ぎと誤りを直しました。直した点の一覧は英語版の11章です）。詳しい英語版は [`M1-EXIT-NOTES.md`](M1-EXIT-NOTES.md) です。これはその要点を、ブロックチェーンの専門知識がなくても読めるように書いたものです。

**数字の見方：**【実測】は実際に動かして測った値、【見積もり】は計算や仮定から出した値です。

---

## 1. ひとことで

- **7日間の試験シーズンは合格しました。** 本番用のプログラムを使い、手元の試験用チェーンで20倍に早回しして行いました（devnet などの公開ネットワークではありません）。1,000体のボットが7日分（早回しで約8時間40分）遊び、わざと部品を落としたり、妨害したりしても、ゲームは最後まで正しく進みました。誰でも使える検証ツールで記録を確かめたところ不正はなく、わざと記録を書き換えた30種類の改ざんはすべて見抜けました【実測】。
- **ただし、完了の確認項目がすべて「合格」になったわけではありません。** 自動テストのうち2つ（G14 と `inproc_day`）が不合格です。原因はゲームではなく**テストの数え方**です。わざと「早すぎる行動」を試す役のボットがいて、その断られた回数を「失敗」として数えてしまっています。この役を除くと失敗は0件です【実測】。直すのはテストだけで、ゲーム本体は変わりません。ただし直すと「完了時点のコード」が1つ新しくなります。**そのため、M1 はまだ正式な完了にしていません。** テストの数え方を直して、この2つのテストが合格すれば完了です（試験シーズンのやり直しは不要の見込みです）。
- もう1つ見つかった問題があります。**防衛費の払い戻し（ClaimDefence）が、試験では一度も成功していません。** 払い戻しを受け取る口座に、手数料を払うためのお金が入っていなかったためです。合格の条件には入っていませんが、テストプレイの前に直すべき点です。

## 2. 何を作ったか

M1 は「お金を使わずに遊べる最初のシーズン」を作る段階でした。できたものは次のとおりです。

- **ゲームのプログラム（ブロックチェーン上の本体）：** 参加、土地の取得、資源の収集・建設・訓練、部隊の編成、封をした行軍（行き先を隠して出発し、後で公開する）、戦闘の決着、シーズンの開始と終了まで、1シーズン分のルールがすべて入っています。お金の仕組みはまだありません（M2 で作ります）。
- **裏方のプログラム：** 鐘ごとの処理を代わりに進める「キーパー」、画面に表示する情報を配る「ヘラルド」、記録をあとから確かめる「検証ツール」、1,000体の試験用ボット、試験用の小さなブロックチェーンです。
- **ブラウザで遊ぶ画面：** 地図、自分の土地、行軍の作成と追跡、戦闘報告（その場で結果を検証できます）、はじめての人向けの案内、練習、観戦。日本語と英語に対応しています。

## 3. どう試したか

1. **7日間の試験シーズン（いちばん大事な試験）：** 本番用に作ったプログラムをそのまま使い、手元の試験用チェーン（1台の共用マシンの上）で20倍に早回しして、乱数は本物の公開乱数（drand）の過去の記録を使いました。1,000体のボットには13種類の「くせ」があり、その中にはずるをしようとするもの、手数料を払わないもの、でたらめな封を送るものもいます。試験中は43回、部品のどれかを突然止めて再起動しました。攻撃役が9種類の妨害（混雑させて処理を遅らせるなど）を行いました。ただしそのうち2種類（到着の記録の枠をキーパーの入札の上限より高い値で押さえる妨害と、ある地域の鐘の基準の記録（アンカー）を押さえて遅らせる妨害）は、押さえる相手の処理がその時間になく、実際には何も遅らせていません。この2つの効き目はまだ試せていません。また、5,000人分の模擬の観戦アクセス（プログラムで発生させたもので、人やブラウザではありません。4,000件は定期取得、1,000件は常時接続）を、ゲーム内24時間（実時間 約1時間12分）流しました。
2. **一つひとつの命令の試験：** プログラムの命令ごとに、いちばん重い条件で処理量が上限に収まるかを確かめました。偽物の口座を渡す、先回りして口座にお金を入れておく、などのずるも試しました。
3. **画面の試験：** 3種類の画面サイズと2つの言語で全画面を撮影し、文字のはみ出し、押しにくいボタン、読み上げソフトへの対応を確かめました。自動操作で「参加→土地→建設→偵察→行軍→戦闘報告→検証」を日本語と英語の両方で最後までやりました。観戦画面をゲーム内の24時間（実時間 約1時間12分）開いたままにして、メモリが増え続けないことも確かめました。この2つは、7日間の試験シーズンの環境ではなく、ボット20体・試験用の鍵の小さな試験環境で行いました（試験シーズンのチェーンはオーナーの観戦のために一時停止したままで、参加を受け付けられないためです）。
4. **これまでの段階の試験をすべてやり直しました**（夜間の短い試験、負荷試験、遅延の測定など）。夜間の短い試験は5回行い、2回目だけ、試合が終わった後の36秒間の負荷測定で応答が遅くなり不合格でした（共用のマシンが一時的に重かったためと見ています）。3〜5回目は3回続けて合格し、決まりどおりの「3回連続合格」を満たしました【実測】。

## 5. 人が遊べるようになる前に、まだ足りないもの

1. **テスト2つの数え方を直す**（小さな作業です）。
2. **払い戻しを受け取る口座に手数料分のお金を入れる仕組み**と、それが動くことの確認。試験環境の設定でお金を入れる方法なら、キーパーのプログラムは変わらず、試験シーズンのやり直しは要りません（キーパー側で手数料の払い手を変える方法だと、やり直しが必要になります）。
3. **画面の修正2つ：** (a) シーズン終了後に着く行軍を画面が作れないようにする。(b) 自分の土地が守られている間は、他の勢力の土地を行き先に選べないように灰色にし、守りが切れる時刻を見せる。どちらもプログラム側では既に断るので、ずるはできません。画面が先に止めるための修正です。
4. **入口のURL：** いまはサイトの入口（`/` と `/frontier`）が古いゲームの画面に飛びます。新しいゲームは `/frontier/frontier/index.html` にあります。招待リンクから新しいゲームに着くようにする必要があります。
5. **devnet（試験用の公開ネットワーク）で動かすための部品：** 暗号化された通信（HTTPS）への対応、公開ネットワーク用のキーパーの読み取り方法、本物の公開乱数への接続、シーズンを始めるための管理ツールなど、手順書に挙げた8項目です。どれもプログラムの作業で、devnet には何もしていません。
6. **運営の準備：** 画面と中継サーバーを置く場所（サーバーとドメイン）、2つ目のキーパーを誰が動かすか、招待の方法、手数料の肩代わりの量（手順書の初期値は、1人1日40回（0〜6日目）、その後は20回）、試験用SOLの用意。

## 6. オーナーにお願いしたい判断

1. **非公開のテストプレイ（50〜200人、お金なし、devnet）を行うか。**
   - 必要なもの：上の5.の1〜6、置き場所（サーバーとドメイン）、招待の方法、手数料の肩代わりの量、試験用SOL（今の設定のままなら約100〜135 SOL、小さい設定なら約37〜43 SOL【見積もり】）。devnet での一つひとつの操作（配置、入金、シーズンの告知、サーバーの起動）にも、そのつど承認が必要です。
   - おすすめ：まず5.の1〜5（プログラムの作業だけで、devnet には触れません）を進めることを承認していただき、テストプレイそのもの・日程・予算は、それが終わった時点で決めていただく形です。
2. **防衛用の積立（D18）の最終値：** 20 SOL のまま、1鐘1地域あたりの上限 0.2 SOL、キーパー1日あたりの上限 2 SOL でよいか。5万人規模でも、攻撃された鐘の約1,950回分をまかなえます【見積もり】。200人のテストプレイなら 2 SOL の小さい設定でも足ります【見積もり】。
3. **キーパーの支払い用の鍵に入れておく額の目安（`r99_reveals`）：** 3万人までは 150、5万人までは 300 にするか。今の初期値 4,000 のままだと、キーパー1つあたり 32〜65 SOL を寝かせることになります【見積もり】。7日間の試験（1,000体）では、1鐘あたりの公開は多くても8件でした【実測】。
4. 以前からの判断（急ぎではありません）：遅れて賭ける人の値段（D22、2.0 のまま推奨、M2 の前まで）、遺跡の役割（D24、M3 の前まで）、GitHub への push（そのつど承認）。

## 7. わかっている限界

- **手元の試験用チェーンだけです。** すべて、1台の共用マシンの上の試験用チェーン（20倍の早回し）で動かしました。devnet では何も動かしていません。devnet での暗号の計算や口座の維持費は、まだ確かめていません。
- **攻撃の費用（C4）は見積もりです。** 計算のモデルから出した値で、実際の攻撃で測ったものではありません。最低チップだけでは足りず、防衛用の積立と150以上の鍵がそろって初めて足ります。本当に足りるかは M4 の長期試験で決めます。
- **防衛費の払い戻しは、試験ではまだ一度も成功していません**（上の1.）。
- **ボットの結果とシミュレーターの比較（合格の条件の外）は測っていません。**
- **妨害が重なった時間の遅れ：** 早回しの試験で妨害が重なった時間に、最大で154スロット（実時間 約1分）止まった処理と、最大で1,720スロット（実時間 約11分半）かかった決着がありました。7日間を通した99%の値は目標内です。
- **妨害9種類のうち2種類は、効き目を試せていません**（上の3.）。
- **はじめての人向けの流れと観戦のメモリの確認は、試験シーズンとは別の小さな試験環境**（ボット20体、試験用の鍵、ゲーム内2日）で行いました。
- **観戦者5,000人は模擬のアクセス**で、人やブラウザではありません。
