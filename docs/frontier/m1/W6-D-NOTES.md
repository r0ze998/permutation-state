## 3. What the onboarding run found (and what was fixed)

| # | Finding | Fix | Owner of any remainder |
|---|---|---|---|
| F1 | **Train and Garrison could never be submitted**: `min="1" step="100" value="100"` makes the default a step mismatch, and Chromium's constraint validation then blocks the form's submit event silently (no notice at all). Muster (`min=100 step=100`) and practice troops (`step=50`) refused any other count | `step="1"` on the four fields; `web-frontier-playtest.test.mjs` checks every literal number field of the page sources | — |
| F2 | **Resident actions stayed disabled on a holding the program takes as final.** The program flips provisional → final lazily inside the next resident action that carries the holding's Province (§5.6 step 5: state 1, `now ≥ final_ts`, cohort closed); nothing else writes state 2, but the page waited for state 2 before enabling Muster, Garrison, Explore or Depart — a deadlock for every new player | `fland.{cohortClosed, finalityDue, isFinal}` mirror `frontier-abi::prologue::{cohort_closed, finality_due}`; `actionBlocks` and `checkMarch` use them (the holding's own Province only) | — |
| F3 | **The home province lags.** The keeper skips quiet provinces in batches (resolved_next 24 at bell 40 in the run), so a player's province is usually more than one bell behind and every resident action shows NotResident until "catch up" is tapped; at 20× the caught-up window (≈ 1 bell) was often gone before the next poll, and an Explore sent in the window landed a bell later and was refused NotResident | The page asks the keeper (`/f/nudge`) itself once per bell while the viewer's home province lags and the tab is visible; re-reads 4 s after any nudge; a Muster/Garrison/Dissolve/Explore refused NotResident is sent once more after the herald shows the catch-up (not Depart). The manual button stays | **W6-C / architect:** consider keeping provinces with a live holding resolved within 1–2 bells (the relay nudge is one request per active player per bell) |
| F4 | "Your ticket ended" (refile offer) appeared right after filing, before the herald folded the ticket | `ps-fui.ticketSeen`: false at FileTicket, true once the herald shows the ticket; `refileOffer(..., {seen})` | — |
| F5 | The onboarding card ticked "first build" on a fresh holding: a founded Hamlet already produces `base_production(Hamlet)` | `hasBuilt` counts production above the tier's base (`fland.BASE_PROD`, `TIER_BONUS_PCT`, pinned to `catalog.rs`) | — |
| F6 | An empty `<select>` (Muster before any troops) was 38 × 44 at 390 px | `select { min-width: 44px }` | — |
| F7 | The herald serves `permutation-server/web` under `/frontier/`, so the game page is **`/frontier/frontier/index.html`**; `/` and `/frontier` redirect to `/frontier/`, which is the **v9 page** (it then fails on `/api/lobby`) | none in W6-D's paths (the web's relative imports need the web root) | **W6-C (herald) / integrator:** redirect `/` and `/frontier` to `/frontier/frontier/` (or serve `web/frontier` there with the shared modules mapped); the playtest runbook (W6-E) should give the full URL |
| F8 | Chromium logs every 404 as a console error: the page reads per-bell herald files before they exist (`/h/bell/{b}/region/{r}` 12–17 per run, `/h/province/{P},{Q}/{b}` 7–9 per run) and treats NotFound as "not yet" | the live run counts them per path (`summary.json` `notFound`) instead of failing on the console line; other console errors still fail | **W6-C (herald):** an explicit "not yet" answer (e.g. 200 `{pending: true}`) would keep a player's console clean |
